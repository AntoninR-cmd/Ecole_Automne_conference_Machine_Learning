### Grille d’évaluation croisée

::: info
À remplir par chaque groupe pour chaque autre groupe, sur une échelle de 1 à 5, avec 5 = excellent). A remplir pour le **19 novembre** impérativement.
:::

==Groupe évaluateur== : Anton Tyurin, Edgar Pierres, Augustin Barnerias ==Groupe évalué== : Tao Levray, Quentin Rousselin, Clément Jourdren

| **Critère** | **Sous-critères** | **Note (1-5)** | **Commentaires** |
|--------------|-----------------------------|--------------|--------------|
| **1. Pertinence du thème** | Le thème choisi est-il original et complémentaire aux enseignements existants ? | 5 | Thème original, dans la continuité des cours, mais sans nouvelles méthodes. Un approfondissement. |
|  | L’ancrage en sciences du vivant est-il justifié et bien illustré ? | 5 | Thème bien dans les sciences du vivant, mais l'utilité finale n'est pas évidente. |
| **2. Structure et clarté** | La présentation suit-elle une logique pédagogique (méthodologie → technique → application) ? | 3 | Il y a principalement les résultats de comparaison, mais sans apprentissage sur les méthodes. |
|  | Le niveau de détail permet-il une bonne compréhension du sujet ? | 4 | Manque de définitions de vocabulaire propre aux descripteurs audio (mais de la documentation d'explication est jointe (vidéo de 30 min)). |
| **3. Qualité méthodologique** | Les concepts clés sont-ils expliqués de manière accessible mais rigoureuse ? | 2 |  |
|  | Les choix méthodologiques sont-ils argumentés ? | 2 | Sûrement prévu dans l'argumentation de la conférence, mais c'est un test de comparaison de performance de plusieurs méthodes, sans explication des raisons de présélection des méthodes. Exemple : SVM à noyau RBF, sans explication sur pourquoi RBF et pas un autre. |
| **4. Rigueur technique** | Le code (GitHub) est-il fonctionnel et commenté | 4 | Manque de commentaires techniques sur les fonctions et ces paramètres. |
|  | Les résultats sont-ils reproductibles (par ex. y a t-il des graines pour générer les échantillons ?) | 5 |  |
|  | Les données sont-elles bien documentées et adaptées à l’application ? | 5 |  |
|  | Y a-t-il des erreurs techniques ou des approximations ? | 4 | Dire optimal, en vérifiant sur un seul échantillon de données, n'est pas très pertinent. Un seul résultat vu, malgré qu'il y ait plus de données disponibles et qu'il aurait donc été possible de comparer les résultats moyens sur plusieurs graines (tirages). |
| **5. Ancrage applicatif** | L’application en sciences du vivant est-elle pertinente et bien illustrée ? | 3 | Il n'y a pas d'explication à quoi un modèle de prédiction de présence de chant d'oiseau dans l'enregistrement peut servir. |
|  | Les limites de la méthode/thème sont-elles mentionnées ?? | 3 | Peut-être pendant la conférence ? — Plus un points pour le fait de reconnaître le surapprentissage (fréquent) des modèles. |
| **6. Qualité des supports** | Les slides sont-ils synthétiques et d'une forme adaptée ? |  |  |
|  | Le dépôt GitHub est-il organisé (README, structure claire, données accessibles) ? | 5 |  |
|  | Les documents partagés en amont (code, données, slides) sont-ils utilisables et complets pour une réutilisation ? | 5 |  |
|  | Les sources sont-elles citées et fiables ? | 5 |  |
